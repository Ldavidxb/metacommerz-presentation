Strategic Positioning

mcxOS is built on N-Tier Multi-Tenant architecture with Row-Level Security policies and enterprise-grade RBAC (role → permission → role_permission many-to-many on SQLAlchemy ORM). It sits on top of existing operating systems with an Embrace & Replace approach.

System of Record

mcxOS becomes the single source of truth. All master data, transactions, and financial records live here. Legacy systems feed into mcxOS as the canonical data store.

SOR Mode

System of Engagement

mcxOS sits above existing ERPs as the orchestration and user interaction layer. Users work in mcxOS while backend operations continue on SAP/Oracle/D365.

SOE Mode

Embrace & Replace

Phase 1: Embrace — integrate with all existing systems, provide unified view. Phase 2: Replace — gradually migrate workloads as trust builds. Zero big-bang risk.

E&R Strategy

Not rip-and-replace. Not another overlay. A neural network that absorbs your ecosystem and elevates it.

S12

Agentic AI / OODA

74 total agents · 62 full OODA · 4 DB tables · The autonomous layer

Every autonomous agent runs the same four-phase decision loop — no exceptions, no custom wiring. The framework lives in backend/orchestrator/ooda/. Three tiers: 62 Full OODA agents, 40 specialist agents, and 12 audit lifecycle agents.

O

OBSERVE

Agent queries live DB for domain signals. Each wrapped in OODASignal (signal_type, signal_data, severity: info/warning/critical)

O

ORIENT

Signal contextualised with history, policy thresholds, prior decisions, risk metadata → OODAContext output

D

DECIDE

Confidence score 0.0–1.0 assigned. OODADecisionResult: decision, reasoning, action_params, requires_human boolean

A

ACT

Creates DB records, publishes events to agent bus, calls external services. Every action logged to AgentAction

Auto-act @ confidence ≥ 0.85 & value < threshold · Escalate @ confidence < 0.70 or novel pattern · Human sees: observation + reasoning + proposed action → Accept / Modify / Reject

Agent Tiers

Tier A — 62 Full OODA

All extend BaseOODAAgent, run autonomous cycles on configured intervals (5–60 min), persist every observation/decision/action to Aurora DB.

Tier B — 40 Specialist

Purpose-built for specific workflow patterns. Invoked directly by services rather than running continuous loops. Domain-specific logic.

Tier C — 12 Audit Lifecycle

Tier 1 orchestrators + sub-agents for the full audit-to-payment pipeline. Multi-step orchestration with SLA enforcement.

Agent Infrastructure

agent_observation

Every signal detected — logged before orient phase. signal_type + signal_data + severity.

agent_decision

Every decision with confidence score, reasoning text, action_params, requires_human flag.

agent_action

Every action executed — success/fail, result dict, action name, relevant IDs.

agent_config

Per-tenant, per-agent: enabled, interval (5–60 min), confidence_threshold (0.70), auto_act_threshold (0.85), value_threshold, channels.

Loop Manager (loop_manager.py)

Runs each agent on configured interval. Async scheduling, running state tracking, exposes run_agent_once() for manual triggers from Agent Control Centre.

Agent Bus (agent_bus.py)

Event-driven cross-module communication. Agents publish typed events (mrp.reorder_triggered, audit.session_approved, finance.payment_authorised). Other agents subscribe via handle_event().

Human-in-the-Loop: ≥85% confidence + value < threshold → auto-act · <70% confidence or novel pattern → escalate structured recommendation · Human sees observation + reasoning + proposed action → Accept / Modify / Reject

Document Audit — Full Autonomous Pipeline

The most complex module — 20 agents orchestrating from GRN confirmation through AI extraction, audit, approval, posting, and payment authorisation. Zero manual steps on clean documents.

1
GRN Confirmed Event

grn.confirmed → AuditOrchestrator.handle_grn_confirmed() → creates DocumentAuditSession (PENDING or WAITING_DOCUMENT)

2
Document Extraction

extract_document_from_s3() → Textract OCR → Claude Opus 4.5 extraction → FieldMappingService normalisation (5000+ patterns)

3
Audit Comparison

Comparator runs (ThreeWayMatch / Freight / LC / Contract / Pricing / BOM) → tolerance check → risk level → auto_resolve flag → ComplianceMiddleware screening

4
Approval Gate

AuditApprovalAgent: 0 variances + clear compliance + value ≤ $10k → auto-approve. Else → human review queue

5
Discrepancy Resolution

DiscrepancyResolutionAgent → ClassifierAgent (PRICE/QTY/VAT/DUPLICATE) → CollaborationTaskAgent → EntityOutreachAgent (vendor email)

6
Re-Audit Loop

ReAuditTriggerAgent: corrected doc → fresh session · 48h no response → chase · 96h → escalate to dispute

7
Posting Readiness

PostingReadinessAgent validates fiscal period open + GL accounts valid → PostingGateService builds balanced journals → FinanceRecordBuilder creates APBill/ARInvoice/JournalEntry

8
Payment Authorisation

<$25k auto-authorise → PaymentBatchBuilderAgent groups bills · $25k–$100k → finance approver · >$100k → treasury

9
AR Release

ARReleaseAgent releases approved customer invoices into AR billing cycle → ARCollectionAgent monitors for collection

Agent Control Centre

Full REST API (/api/agents/*) + live frontend dashboard. Every team member has a single place to see what agents are doing, review escalations, and override with a click.

Backend API

  • Status, decisions, actions, observations
  • Manual triggers (run_agent_once)
  • Human overrides (accept/reject/modify)
  • Per-agent config management
  • Event bus introspection
  • All endpoints tenant-scoped + authenticated

Frontend Dashboard

  • KPI strip: active agents, pending review, actions today
  • Module grid: agents + status + manual trigger
  • Pending Human Review panel
  • Recent Actions feed
  • Polls: status/30s, decisions/15s
  • Path: /agents → AgentDashboard.tsx

Human Override Flow

  • POST /api/agents/decisions/{id}/override
  • Actions: accept | reject | modify
  • Override reason required
  • Accept/modify → triggers action execution
  • Reject → marks decision rejected
  • Full audit trail on every decision

Per-Agent Configuration

  • enabled — agent on/off per tenant
  • run_interval_minutes — 5 to 60 min
  • confidence_threshold — default 0.70 (below = never auto-act)
  • auto_act_threshold — default 0.85 (above = no human review)
  • value_threshold — $ amount escalation regardless of confidence
  • notification_channels — where alerts route
